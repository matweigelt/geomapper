### A-1 — The green gate does not bound how much of the suite ran. **High.**

The gate is six conditions (`rungeoMapTests.m:249`):

```matlab
ok = (nFail == 0) && manifestOk && warnOk && speedOk && covOk && auditOk;
```

`nInc` — the incomplete count — is computed three lines above, printed in the reconciliation block, and **never enters `ok`**. Separately, `speedOk` is initialised `true` at line 186 and then ANDed over whatever ratio records were left behind; when no speed test runs, the AND is over an empty set and the tick is printed on the strength of nothing measured.

Both are reachable through one environment variable. `GeoMapTestCase.assumeSpeedTestsEnabled` filters on `GEOMAP_SKIP_SPEED`, which eighteen tests call.

**[executed]** — CI run `32492682068`, step *Probe A-1*, `GEOMAP_SKIP_SPEED=1`, `rungeoMapTests("all")`:

```
passed + failed + incomplete = 449 + 0 + 42 = 491
suite size                   = 491
GREEN GATE: PASS
  zero failures      ok
  speed budgets      ok        <- 5 ratio records, all 5 marked weak/graphics
rungeoMapTests returned ok = 1
```

**42 of 491 points did not run — 8.6% of the suite — and the gate returned `ok = 1`.** CI asserts on exactly that return value. The "speed budgets ok" tick was decided by five records, every one of them marked weak.

**Why this matters more here than it would elsewhere.** The doctrine this project runs on is that *the green gate is not the pass count*, and five of the six conditions exist to say so. The one failure mode that makes a suite quietly shrink — filtering — is the one the gate does not watch. It is not hypothetical: **PV-129 moved the filtered count from 1 to 5 when the v1 tree left the target machine, and no gate noticed.** It was caught by a human reading a commit message. The same silence covers 42.

The human reading the log does see the number. `assert(ok, …)` in `ci.yml` does not, and CI is the instrument that runs when nobody is reading.

### A-2 — The `reference` tier asserts against a checked-in artefact, not against its oracle. **Medium-High.**

The tests whose entire purpose is to check against something not built here — oracle O1 (Snyder 1987) and O4 (PROJ) — do not reach either. `TestB1_projection.publishedPointValuesReproduce` and its two neighbours assert against `tc.loadMirrorReference(...)`, which reads `mirror/geomap_mirror/out/reference_values.json` from the working tree (`GeoMapTestCase.m:293`). **[static]**

The independence was real when it was established at Stage 0, and it has since been frozen into a file. Nothing checks the file is still what the mirror computes:

- CI's `mirror` job regenerates the JSON and uploads it as an **artefact**; it does not commit it and does not compare it with the committed copy. **[static, `ci.yml:118–123`]**
- CI's `matlab` job runs in a **separate job on a fresh checkout**, so it reads the committed copy. The two never meet. **[static]**
- `check_acceptance.py` reads the same path the mirror just wrote, so it validates the fresh file, never the committed one. **[static, `check_acceptance.py:28,74`]**

**[executed]** — running the mirror in this session rewrote the committed file:

| key | committed | this environment |
|---|---|---|
| GDAL version | 3.10.3 | **3.12.4** |
| `regrid_mass_closure_floor` | 2.150e-14 | **3.936e-14** |
| two sphere-area totals | — | last 1–2 ULP |

Both floors sit under `TolMass` = 1e-13, so **V7 stays discharged and no number in the toolbox is wrong today**. What is unverified is the *link*: the committed artefact and the live oracle already disagree, in a green tree, and no instrument in the project can say so. The projection values are environment-independent and the risk to them is low; the risk is that this is the mechanism by which a stale reference would go unnoticed, and one measurement has already drifted through it.

Recorded separately as PV-132 in `RECORDS.md` R-026 (branch `claude/v2000-pv130-ledger-sync`, PR #25). The regenerated file was reverted rather than committed there, for the reason above.

### A-3 — No layer range-checks latitude. **Medium-High.**

`geo.readGrid`'s axis picker accepts the variable names `x` and `y` as longitude and latitude (`readGrid.m:516`, candidate lists at lines ~296–300). `geo.grid`'s `mustBeAxis` validates real, finite, strictly monotone, at least two points — **and no angular range** (`grid.m:171–196`). A grep of the whole package finds eleven `mustBeInRange` guards, every one of them on a colour channel, and none on a coordinate. **[static]**

Projected NetCDF is not an exotic input; it is how a large share of gridded geophysics is distributed.

**[executed]** — CI run `32492682068`, step *Probe A-3*. A NetCDF with `x` ∈ [−3e6, 3e6] m, `y` ∈ [−2e6, 2e6] m, `z` random:

```
PROBE A-3 RESULT: readGrid RETURNED a grid.
  Lat range : -2e+06 .. 2e+06   (degrees, per the struct contract)
  Lon range : -3e+06 .. 3e+06
  geo.project on the first node: x = NaN, y = NaN
```

No error. No warning.

**Stated fairly: this does not put wrong numbers on a map.** `geo.project` returns NaN, so the user gets a blank figure. The defect is diagnostic, not numerical — the reader is the last place on the path that could have said *these are not degrees*, and it says nothing, so the failure surfaces several layers downstream as an empty axes with no cause attached. For a toolbox whose error messages elsewhere explain the antimeridian convention in three sentences, that is out of character.

### A-4 — One identifier for every way a NetCDF can fail to open. **Low-Medium.**

```matlab
try
    info = ncinfo(char(name));
catch
    error('geo:readGrid:FileNotFound', 'Could not open "%s" as NetCDF.', name);
end
```

`readGrid.m:289–293`. **[static]** The bare `catch` discards `ME`. A corrupt file, an unsupported HDF5 filter, a permissions failure and a genuinely absent file all arrive at the caller as `FileNotFound` with the real cause gone.

The rule it breaks is the project's own, written eight lines into `+geo/+internal/layout.m`: *"NAMED, NOT SWALLOWED. v1's bare catch made a broken element look like an absent one."* The sibling `catch ME` forty lines earlier in the same file does it correctly — it inspects the identifier, adds context, and rethrows otherwise. This one is the exception, which is why it reads as an oversight rather than a decision.

### A-5 — Category coverage can be switched off by omission. **Low, latent.**

`reportCategoryCoverage` (`rungeoMapTests.m`) skips a suite that declares no `CoveredFunctions`, printing `(no CoveredFunctions declared - skipped)` and leaving `ok` unchanged; and its `catch continue` skips a class whose metaclass will not load, printing nothing at all. **[static]**

**All 23 suites currently declare `CoveredFunctions`**, so nothing is being missed today. It is listed because the failure mode is the same shape as A-1: a condition that is satisfied by the absence of the thing it checks, and a new suite is the natural way for it to arrive.

## What was checked and found sound

An audit that reports only positives has not looked at the negatives.

- **Test discovery is `TestSuite.fromFolder`** (`rungeoMapTests.m:97`), and the empty result is a named error. A renamed or moved suite cannot silently disappear — which is precisely the defect a prior project's audit found, and this project does not have it. **[static]**
- **Every one of the 23 suites carries real assertions**; the leanest is 1.4 verifications per test method and none is a smoke test. **[executed, sandbox]**
- **`readGrid`'s other `catch`** inspects the identifier, adds the missing half of the message, and rethrows unrecognised exceptions. Correct. **[static]**
- **`mcheck` and `provenance_audit` both refuse to report a clean tree unless their own fault-injection self-test passes in the same invocation.** Both re-run clean here: 111 files / 0 problems, and 0 problems / 0 `PROVISIONAL` stamps. **[executed, sandbox]**
- **The frozen acceptance criteria hold in a second, independent environment**: 74 criteria, 0 breaches, against PROJ 9.5.1 and GDAL 3.12.4 rather than the recorded baseline's GDAL 3.10.3. **[executed, sandbox]**
- **The MATLAB leg does not require the target machine.** CI provisions R2026a on a hosted runner; this audit's MATLAB evidence was obtained without a bridge. **[executed]**

## Proposed remedies — **not applied, and not to be applied without agreement**

Listed so the findings are actionable, not because any of them is agreed.

- **A-1.** Add the incomplete count to the gate as a *declared* number rather than a bound: the run states how many points it expects to filter and why, and a mismatch is red. `5` is the current answer and PV-129 is the reason. Separately, make `speedOk` refuse an empty record set unless the speed tier was explicitly deselected, so the tick cannot be earned by measuring nothing.
- **A-2.** Have the MATLAB leg assert the committed JSON against a hash the mirror writes beside it, or have CI diff the regenerated file against the committed one and fail on disagreement. Either turns "the oracle was independent once" into "the oracle is independent now."
- **A-3.** Range-check the angular axes where the grid is constructed, not where it is read, so every path is covered by one guard.
- **A-4.** `catch ME` and carry the cause.
- **A-5.** A missing `CoveredFunctions` is a finding, not a skip.
